# 双向路径（BDPT）连接候选优化说明

## 图形入口（主入口）

双向路径追踪的完整交互入口是浏览器窗口，命令行只做辅助核查。

1. 启动：`npm start`，打开 `http://localhost:5173/`。
2. 左侧 **BDPT 内核** 面板的 **「连接候选优化」** 下拉框选择连接模式：
   - **基线：全量可见性连接（运行参照）**：旧双向路径行为，每个 `(s,t)` 候选都发射
     线段可见性光线，作为不可伪报的运行参照。
   - **几何/界面剪枝（图像与基线一致）**：廉价几何/事件探针先行，仅对可证明零贡献的
     界面开口外穿越做硬剪枝，其余候选仍完整求值并保留全部 MIS 记录，逐像素与基线一致。
   - **剪枝 + 分层预算（逆概率加权）**：在剪枝基础上对每像素样本的可见性检查施加预算，
     超额候选分层抽取，被抽中者乘 `1/p` 补偿，期望无偏。
3. **「每像素可见性预算」** 滑杆仅在分层模式下启用。
4. 渲染完成后，内核面板下方的 **「连接成本分解」** 给出每像素候选数、可见性光线数、
   硬/软剪枝数、预算递延与归还、光线阻断率。
5. 右侧 **「选定路径核查」** 的「生成并连接该像素的子路径」按钮调用真实双向路径实现，
   顶点表新增 **介质侧** 列，状态行汇总规划器成本；不存在固定数据冒充的间接照明。
6. 中部工具栏的 **仅间接 / 仅直接 / PT 参照 / 差异×4** 视图对照变更前后的间接照明与
   路径贡献；顶视图绘制真实连接段与遮挡关系。

场景 **「透明界面窄开口（介质交换）」** 提供带实体墙与介质区域的边界条件场景。

## 命令行辅助入口（不替代图形入口）

- `npm test`：全部单元测试，含连接候选优化的边界条件与无偏性测试。
- `npm run check`：原有 MIS / 密度 / 可见性 / 亮度数值核查。
- `npm run bench:connect -- [scene] [spp] [budget]`：三模式连接基准，输出耗时、连接
  成本分解与相对基线的统计误差；护栏失败时以非零码退出。
- `npm run stat:connect -- [scene] [trials]`（环境变量 `BUDGET` 可调预算）：相同种子下
  三模式的均值/方差对照。

## 连接候选优化的计算顺序

`src/core/connect.js` 的 `planConnections` 对每个像素样本按以下顺序处理候选，
每一步拒绝都带可审计状态，并把该候选的可见性预算归还（`budgetRefunded`）：

1. **枚举候选**：与 `evaluateAllStrategies` 完全相同的 `(s≥1, t≥1)` 对，加上发光体
   命中的 `t=0` 前缀；所有有效策略与原 MIS 计权方式保持不变。
2. **事件条件（软）**：`splitFeasibility` 判定镜面（delta）端点不可任意连接。软拒绝只
   登记预过滤，仍走完整求值以保留 MIS 记录。
3. **相机响应（软）**：`s=1` 时投影到像素，出界候选由 `evaluateStrategy` 提前返回、不
   发射可见性光线。
4. **几何上界探针（不发射光线）**：纯点积/叉积计算端点余弦与 `r²` 上界；零余弦登记为
   软预过滤。
5. **介质界面硬剪枝**：连接段严格分居界面两侧（带浮点/近墙容差，相切不剪）且穿越点
   落在所有可通行开口之外时，因实体墙必然阻断该可见性光线，直接拒绝为
   `interface-opening-miss`，不发射光线。这是唯一的硬剪枝，且与实体几何共面，保证
   不会丢弃任何基线本会接受的贡献。
6. **分层预算（仅 optimized）**：剩余需可见性检查的候选若超过预算，用互质步长在候选环
   上均匀保留 `budget` 个，保留概率 `p=budget/count`；被抽中候选的加权贡献乘 `1/p`，
   使估计量期望无偏，稀有有效端点不会因枚举位置被系统性吞掉。
7. **完整求值与 MIS**：所有保留候选调用原 `evaluateStrategy`，MIS 权重、几何项、可见性
   与计权路径完全复用旧实现，禁止用「少连接」制造暗图来冒充提速。

### 撤回条件

`scripts/bench-connect.mjs` 内置护栏：若剪枝模式相对基线出现均值偏差、RMSE 超过精确
匹配容差，或可见性工作量未下降，脚本以非零码退出。出现连接成本及统计误差之外的行为
退化时，应撤回对应优化（将连接模式保持为 `baseline`）。

## 介质交换与不重复计数

`swapInterfaceMedia` 只翻转介质区域的平面法线朝向与正侧掩码，不改动任何 BSDF、几何或
采样。测试 `test/connect.test.js` 核查交换前后同一光路的每条策略加权完全一致，贡献
不会在两个介质侧各计一次。
